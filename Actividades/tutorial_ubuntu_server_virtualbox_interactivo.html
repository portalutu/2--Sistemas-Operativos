02Crear la máquina virtual en VirtualBox

La VM debe simular un servidor pequeño. No necesita interfaz gráfica, por lo que se prioriza RAM suficiente, disco ordenado y red correcta.

Nombre
ubuntu-server-lab
Usar nombres claros facilita identificar VMs.
RAM
2 GB mínimo
4 GB recomendado si se usará Docker.
CPU
2 vCPU
Suficiente para prácticas de servidor.
Disco
40 GB VDI
Dinámico para ahorrar espacio físico.
1

Nueva VM

VirtualBox → New → Name: ubuntu-server-lab → Type: Linux → Version: Ubuntu 64-bit.

2

Memoria y procesador

Asignar 2048 MB o más. En procesadores, asignar 2 vCPU si el equipo anfitrión lo permite.

3

Disco virtual

Crear un disco VDI dinámico de 40 GB. En laboratorio, esto permite practicar particiones sin consumir todo el espacio inmediatamente.

4

Montar ISO

Settings → Storage → Optical Drive → seleccionar la ISO de Ubuntu Server descargada.

5

Red

Para prácticas iniciales usar NAT. Para que otros equipos de la LAN accedan al servidor, usar Bridged Adapter.

03Instalación guiada de Ubuntu Server

Durante la instalación, el objetivo no es “hacer clic rápido”, sino entender cada decisión: idioma, teclado, red, disco, usuario y servicios.

1

Arranque desde ISO

Iniciar la VM. Elegir Try or Install Ubuntu Server.

2

Idioma y teclado

Elegir idioma de instalación y distribución de teclado. Probar caracteres como /, :, - y _.

3

Red inicial

Si la VM está en NAT, normalmente recibirá IP por DHCP. Verificar que aparezca una dirección IPv4.

4

Proxy y mirror

Dejar proxy vacío salvo que la red del centro educativo lo requiera. Aceptar el mirror sugerido si responde correctamente.

5

Disco

Elegir el esquema de particionado. Para esta práctica se usará LVM para mostrar administración flexible de volúmenes.

6

Usuario inicial

Crear un usuario administrador, por ejemplo: nombre Estudiante, usuario sysadmin, servidor ubuntu-lab.

7

OpenSSH

Marcar instalación de OpenSSH Server si se desea administrar la VM por terminal remota.

04Particionamiento de disco y uso de LVM

LVM permite crear una capa lógica sobre el disco físico. En lugar de depender solo de particiones rígidas, se trabaja con Physical Volumes, Volume Groups y Logical Volumes.

EFI
512 MB
/boot
1 GB
LVM PV
resto del disco
LV raíz
/
20 GB para sistema base, paquetes y servicios.
LV home
/home
8 GB para usuarios y archivos de práctica.
LV swap
swap
2 GB para laboratorio. Ajustar según RAM.
Analogía didáctica
Un disco físico es como un terreno. Las particiones son lotes. LVM agrega una administración flexible: junta espacio en un grupo y luego reparte volúmenes lógicos según necesidad.
PV
Physical Volume
Disco o partición entregada a LVM.
VG
Volume Group
Grupo de almacenamiento formado por uno o más PV.
LV
Logical Volume
Volumen usable como /, /home o swap.
verificación posterior a la instalación
lsblk
sudo fdisk -l
df -h
sudo pvs
sudo vgs
sudo lvs
Precaución
No modificar particiones de un equipo real sin respaldo. En esta práctica se trabaja sobre un disco virtual para poder aprender sin poner datos reales en riesgo.

06Configurar IP con Netplan

Ubuntu Server usa Netplan para declarar la configuración de red en archivos YAML dentro de /etc/netplan/. El nombre de la interfaz puede ser enp0s3, ens33, eth0 u otro.

DHCP es apropiado para una primera instalación o para redes NAT de VirtualBox.

/etc/netplan/00-installer-config.yaml
network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: true

IP estática es útil cuando el servidor ofrecerá servicios como SMB, SSH, Docker o páginas web internas.

IP estática de ejemplo
network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: false
      addresses:
        - 192.168.1.50/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses:
          - 1.1.1.1
          - 8.8.8.8
aplicar configuración
sudo nano /etc/netplan/00-installer-config.yaml
sudo netplan generate
sudo netplan try
sudo netplan apply
ip a
ip route
ping -c 4 8.8.8.8
ping -c 4 google.com
netplan try
Usar netplan try cuando se trabaja remotamente. Si la configuración rompe la red, Netplan puede revertir el cambio si no se confirma.
07Instalar SMB/Samba y compartir /srv/compartida

Samba permite compartir carpetas entre Linux, Windows y otros sistemas mediante el protocolo SMB.

instalación y carpeta compartida
sudo apt update
sudo apt install samba -y
sudo mkdir -p /srv/compartida
sudo groupadd smbusers
sudo chown -R root:smbusers /srv/compartida
sudo chmod -R 2770 /srv/compartida
sudo usermod -aG smbusers alumno
sudo smbpasswd -a alumno
bloque para /etc/samba/smb.conf
[compartida]
   path = /srv/compartida
   browseable = yes
   read only = no
   valid users = @smbusers
   create mask = 0660
   directory mask = 2770
probar servicio
testparm
sudo systemctl restart smbd
sudo systemctl enable smbd
sudo systemctl status smbd
smbclient -L localhost -U alumno
Acceso desde Windows
Desde el Explorador de archivos: \\192.168.1.50\compartida. Usar el usuario Samba creado con smbpasswd.
08Instalar Docker Engine y Docker Compose

Docker permite ejecutar aplicaciones en contenedores. Docker Compose permite describir varios contenedores relacionados en un archivo YAML.

instalación oficial desde repositorio Docker
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo ${UBUNTU_CODENAME:-$VERSION_CODENAME}) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker $USER
newgrp docker
docker --version
docker compose version
docker run hello-world
Reinicio de sesión
Después de agregar el usuario al grupo docker, puede ser necesario cerrar sesión y volver a entrar para que el cambio tenga efecto.

10Apéndice: referencia rápida de YAML

YAML es un formato de texto usado para configuración. Es legible, pero muy sensible a la indentación.

clave: valor
Define una propiedad simple. Ejemplo: version: 2.
indentación
La jerarquía se indica con espacios. No usar tabuladores.
listas
Se escriben con guion. Ejemplo: - 192.168.1.50/24.
strings
Pueden ir sin comillas, pero conviene usar comillas cuando hay caracteres especiales, como puertos: "8080:80".
comentarios
Comienzan con #. Sirven para explicar líneas.
Ejemplo YAML simple
Lista de servicios
yaml
servicios:
  - ssh
  - samba
  - docker
Ejemplo con objetos
Usuario
yaml
usuario:
  nombre: alumno
  grupos:
    - sudo
    - docker
  activo: true
Errores frecuentes
Los errores más comunes son mezclar tabs con espacios, cambiar la indentación, olvidar los dos puntos o escribir mal una lista. En Netplan y Docker Compose, un espacio mal puesto puede impedir que la configuración cargue.
